# 同账号跨端消息与文件完成同步

本文定义桌面如何合并 HTTP、WebSocket、服务器历史和 SQLite 缓存。入口实现见 [desktopMessageSync.mjs](../src/main/utils/desktopMessageSync.mjs)，功能历史见 [CHANGELOG](../CHANGELOG.md)。

## 消息与控制事件

后端向本人其他设备镜像文字、文件占位、文件完成和 AI 提问。私聊发送者视角的 `contactId` 始终为对端，`sessionId` 与 HTTP 接受结果一致；文字携带稳定的 `clientMessageId`，不能生成自聊会话。

| 类型         | 桌面处理                                                                 |
| ------------ | ------------------------------------------------------------------------ |
| 2            | 文字；按 `messageId` 合并，本人镜像不增加未读                            |
| 5            | 文件消息或上传占位；保留本地源路径与现有最终状态                         |
| 6            | 合并最终文件名、大小、类型、`status=1` 和会话字段；持久化/展示仍为类型 5 |
| 14 / 15 / 16 | AI 回复开始、累计内容与结束事件；更新同一回复及终态                      |
| 17           | 已读回执控制事件，不进入聊天列表                                         |
| 18           | 同账号私有备注同步，不产生聊天消息或未读                                 |

本人 AI 提问只出现一次。机器人回复作为对端消息按当前可见性处理未读，不能因为流式片段数增加多条未读。

## 合并不变量

HTTP 接受结果、WebSocket、历史和本地缓存都按 `messageId` 合并。完成事件可以先于占位到达；最终元数据不能被迟到 type 5、HTTP 接受或本地失败回调回退。完成较早附件不能覆盖会话中较新消息的预览。

SQLite 写入按账号和 `messageId` 串行执行，避免并发读取旧状态后相互覆盖。新旧库自动迁移 `client_message_id`，并保留原始路径和客户端键。账号变化后，旧连接、异步响应和排队写入不能进入新账号。

文字先保存到当前账号 SQLite 待发队列，再使用稳定 `clientMessageId` 发送。本人回显只有在用户、会话、对端和客户端键全部匹配时才能确认待发草稿；确认后立即移除待发气泡和持久记录。随后到达的 HTTP 超时不能重新创建已接受草稿，陌生用户或不匹配会话也不能确认它。
