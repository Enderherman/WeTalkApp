# 同账号跨端镜像与文件完成事件

后端对本人其他设备镜像文字/文件占位/文件完成消息（type 2/5/6）以及AI提问。私聊发送者视角的contactId仍是对端，sessionId与HTTP结果一致，文字带clientMessageId；17/18控制帧不作为聊天回显。

桌面处理规则：

- 按messageId合并HTTP、WebSocket、服务器历史与本地缓存，不追加重复气泡。本人的镜像不增加未读。
- type 6合并最终fileName/fileSize/fileType/status及完整会话信息，落库时仍为type 5；即使完成早于占位也能恢复该文件消息。控制帧不会再次计入未读，完成旧附件不覆盖最新会话预览。
- 已确认的文件状态和最终元数据不被迟到的type 5占位、HTTP接受或本地失败回调回退。本机源文件路径仍保留供重试/保存操作使用。
- SQLite写入按账号+messageId排队，避免两个并发读取旧值再覆盖的竞态；clientMessageId列自动迁移。
- 自己的文字回显只有在用户、会话、对端、客户端键全部匹配时才确认outbox。立即移除待发气泡并删除对应持久草稿；若HTTP随后超时，不会复活它。其他用户或不匹配会话不能确认草稿。

验证：`npm run test:message-mirror` 20项相关测试。问题用例修改前确认失败（最终大小仍旧值、完成后回退待上传）；修复后覆盖type6重复/倒序、HTTP与WS先后两种顺序、晚到HTTP超时、陌生回显拒绝、旧附件不覆盖新预览、SQLite新库/旧库迁移/并发写入、原始路径与客户端键保留。真实同账号浏览器+Electron镜像验证另由工作区审计记录，不以模块测试代替。
